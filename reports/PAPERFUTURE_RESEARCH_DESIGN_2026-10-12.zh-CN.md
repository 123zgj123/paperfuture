# PaperFuture 研究设计与评测方案

日期：2026 年 10 月 12 日。研究与评测领域：多模态大模型自进化中的可解释性、Agent security、AI4EDA 设计。系统中的模型能力通过 API 调用，不以本地 GPU、模型训练或自建推理服务为前提。代码审查基于本仓库提交 `c79a5191d251fb2de3448f01afe29fa4bb1f93e2`。

PaperFuture 的核心研究问题是：**科研代理能否从一个具体研究方向的发展轨迹中理解技术如何演进，进一步模拟尚未发生的技术跃迁，预测有价值且有意义的未来研究 idea？** 本文保留原方案的完整主线，优化各环节的定义、实现和评测，不增加独立的研究模块或改变论文方向。

模块接口、数据结构、逐文件改造与控制循环进一步见 [系统模块与代码设计](PAPERFUTURE_SYSTEM_DESIGN_2026-10-12.zh-CN.md)，配套 [系统框架图](../figures/paperfuture_framework_zh.png) 与 [英文论文图 PDF](../figures/paperfuture_framework_en.pdf)。

三个领域采用同一条方法链路和同一套评测原则，分别构建文献与发展轨迹。这里将第一个领域具体理解为：多模态大模型在自反馈、自修正或持续改进过程中，其能力与内部机制变化能否得到可信解释。每个领域内再选择足够具体的小方向，防止把跨度过大的文献混成一张含义模糊的图。

PaperFuture 本身执行文献处理、图构建、idea 推演和价值判断，模型推理均可由外部 API 提供；本地只需常规的数据存储、索引和流程调度。验证某个生成 idea 可能需要模型训练、访问内部激活或运行 EDA 工具，那属于后续研究验证，不是运行 PaperFuture 的前置条件。资源后续补齐时，应增加评测覆盖和验证深度，而不改变系统主线。

系统流程保持为：

```text
领域论文元数据
    ↓ 检索与筛选
高质量且覆盖关键发展阶段的 selected data
    ↓ 抽取研究状态和技术变化
有方向且边带跃迁权重的研究发展图
    ↓ LLM 理解轨迹并选择方向与幅度
模拟技术跃迁
    ↓ world model 模拟、讨论和评价
候选 idea、研究价值、可行性与反馈
    ├─ 已达到条件 → 输出最终 idea 及价值判断
    └─ 仍需探索 → 调整下一跳，全局最多四轮
```

PaperFutureBench 以预测后续论文中的研究方向为主评测。人工评价和少量可行性实验用于补充判断研究价值，避免只奖励“像未来论文”的文字。时间快照、来源记录和预算记录是支撑这条流程的实现要求，不单独包装成研究贡献。

本文中的数据规模、阈值和实验数量均为建议的起步配置，不是已经取得的结果。当前已完成的是代码审查与离线回归，验证结果见文末。

## 一 研究问题需要怎样收紧

“现有系统被历史数据影响，因此无法预测有价值的未来 idea”把几个不同问题混在了一起。科学推理本来就需要历史知识；真正需要检验的是，系统是否过度集中于熟悉的方法、能否识别可以改变的假设，以及它挑选的方向是否值得投入。

已有人工研究发现，LLM 生成的研究建议在特定任务中可以被评为更有新意，但生成多样性和自我评价仍有明显问题。因此，论文不宜把“LLM 不会产生创新”作为已证实的前提。更稳妥的出发点是：**高表面新颖度、丰富的候选数量和可靠的研究价值判断，并不天然一致。** [Si 等人的研究](https://arxiv.org/abs/2409.04109)

围绕原流程，可以提出三个可检验假设。

| 假设 | 应观察到的结果 | 什么结果会削弱它 |
|---|---|---|
| 研究轨迹及跃迁权重有助于预测未来 idea | 同一批论文、相同上下文预算下，对后续研究的机制级命中提高，重复旧工作的比例下降 | 去掉边和跃迁属性后结果不变，或仅增加文献数量就能获得同样提升 |
| 有依据的反馈比反复自由辩论更有效 | 错误假设更容易被修正，同时有效的新颖候选保留率更高 | critic 分数提高，但专家评价、预测正确性或真实实验收益下降 |
| 动态停止能节省有效预算 | 相比固定四轮，在预先规定的质量容忍范围内减少总成本 | 节省成本主要来自漏掉后来有效的方向，或只对容易的题目有效 |

这里要区分三个结果变量：**未来有人研究了什么、一个想法在提出时是否值得研究、它实际能否产生收益。** 它们可以相关，却不能相互替代。后来发表的论文只是观察到的一部分未来；没有对应论文的想法可能有效，录用论文也未必代表重大突破。

同质化也需要分层测量：重复用词只是表面现象；更关键的是候选是否反复使用同一机制、依赖同一假设，以及不同运行是否总进入相同的研究分支。先测这些可观察现象，再讨论历史知识、检索和评价策略可能造成的影响。仅凭输出集中，不能归因到模型的训练数据。

## 二 与已有工作的区别必须建立在具体机制上

截至本文日期，原始设想的多个组成部分已经有直接相关工作。论文需要正面比较，不能以“第一次用图生成科研 idea”或“第一次用未来论文评测”为主要贡献。

| 相关工作 | 与本方案直接重合的部分 | PaperFuture 应进一步回答的问题 |
|---|---|---|
| [Chain of Ideas](https://arxiv.org/abs/2410.13185) | 用文献发展链辅助研究构思 | 有证据的分叉、假设变化和多来源机制迁移，是否优于线性发展链 |
| [Graphs of Research](https://arxiv.org/abs/2605.14790) | 构造带边特征的论文演化 DAG，并用于监督微调 | 在固定文献和模型下，机制变化的表示与使用是否有额外作用；不能只换图的名称 |
| [FlowPIE](https://arxiv.org/abs/2603.29557) | 文献探索与 idea 演化联动，包含搜索和跨域变异 | 相同调用预算下，技术跃迁表示与模拟反馈是否带来额外收益 |
| [Evolving Idea Graphs](https://arxiv.org/abs/2605.04922) | 用图表达和修改候选 idea | 有文献依据的历史发展图，能否更有效地支持未来机制预测 |
| [AI co-scientist](https://arxiv.org/abs/2502.18864) | 生成、讨论、竞争和演化假设 | 模拟反馈是否得到独立校准，以及何时应停止讨论并做实验 |
| [HindSight](https://arxiv.org/abs/2603.15164) | 匹配未来论文，并借助引用和发表信号评价 | 如何避免把跟随未来热点当成科学价值，如何保留未被发表覆盖的有效方向 |
| [IdeaForecastBench](https://fenghaili.com/papers/idea-forecast-bench/) | 以主题和截止时间构造滚动预测，匹配后续文献流 | 如何增加模型时间隔离、机制级核验和真实研究效用证据 |
| [PreScience](https://github.com/allenai/prescience) | 预测科学贡献、参考文献和后续影响等 | 开放瓶颈驱动的构思与已给作者、参考文献等条件的预测，应如何分开评价 |

由这些工作推导出的定位是：**PaperFuture 通过带技术跃迁幅度的研究发展图，引导 LLM 模拟未来跃迁，再利用 world model 的反馈修正后续探索；PaperFutureBench 检验这些预测是否对应后来出现的有意义研究。** 差异应体现在跃迁权重怎样定义、图怎样真正影响预测、模拟反馈怎样改善结果，而不仅是组件名称不同。

尤其需要正面比较 GoR：其边特征包括引用所在章节、影响信号、时间差与图结构，并将图序列化后用于监督微调。PaperFuture 可以进一步研究“假设、机制和能力边界改变了多少”这一技术含义，并在 API 推演时使用它来选择下一跳；这个区别需要通过同资料、同模型的对照证明，不能仅因采用 API 就声称方法创新。[GoR 方法与边特征定义](https://arxiv.org/html/2605.14790v1)

论文可以围绕这条完整链路组织贡献，但每个环节的必要性都要由对照实验说明。尤其要与发展链、演化 DAG 和迭代构思方法直接比较，才能判断原方案的细化是否产生了可重复的增益。

## 三 文献收集与选择要围绕轨迹覆盖

### 从具体瓶颈定义领域

三个领域应并列开展，领域内部的研究线分别建图。下表是文献划分建议，不是新增系统模块，也不是预先替模型指定答案。

| 领域 | 可以跟踪的具体研究线 | 划分时需要注意 |
|---|---|---|
| 多模态大模型自进化中的可解释性 | 自修正前后的推理依据是否变化；自反馈是否修复视觉依据缺失；能力提升与内部机制变化的关系；自动解释的忠实性与可验证性 | 区分模型真正改进、输出解释变得更好看，以及解释器自身变强；不能把一般视觉问答性能论文全部算入 |
| Agent security | 工具输出中的间接提示注入；来源和权限隔离；跨步骤污染传播；攻击适应与防御泛化；安全措施对正常任务的影响 | 区分攻击入口、攻击者能力和代理权限；一般聊天越狱不能自动视为工具代理安全 |
| AI4EDA 设计 | RTL 生成与修复；验证反馈驱动的设计改进；功耗、性能、面积约束下的优化；工具调用与设计流程自动化 | 区分语法正确、功能正确和物理实现收益；任务、工艺与约束不同的结果不能直接连成进步链 |

对于第一个交叉领域，单独标注“自进化”和“可解释性”两条基础脉络，在有证据时连接二者；如果直接交叉文献尚少，应保留这个事实，而不是编造一条成熟的发展史。相关种子可以从 [MAIA](https://arxiv.org/abs/2404.14394) 所研究的自动模型解释入手，但 MAIA 本身不能代表整个自进化方向。Agent security 可从 [AgentDojo](https://github.com/ethz-spylab/agentdojo) 的工具代理安全问题开始扩展；AI4EDA 可从 [ChatEDA](https://arxiv.org/abs/2308.10204) 的设计流程自动化及其前驱、后继工作展开。种子只用于查找，最终纳入哪些论文仍取决于任务和时间边界。

建议每个领域先尝试收集约 10,000–30,000 条宽范围元数据，筛出约 1,000–3,000 篇相关记录，再对约 200–400 篇轨迹关键文献获取可用全文并做结构化抽取。交叉领域的直接相关文献可能少于这个范围，数量应由召回率和领域密度调整，不能为了达到规模混入无关论文。每个研究任务给模型的详细证据包可以从 20–40 篇文献中的相关片段起步，同时保留该小方向的完整阶段图摘要。

元数据负责发现论文，包括规范 ID、标题、作者、摘要、版本日期、参考文献和来源。**机制建模还需要全文中的方法、假设、实验和局限性片段。** 只有摘要时可以建立初步节点，但应标注信息不完整，不能补写成确定的技术演化史。

arXiv、OpenReview 和出版页面可提供论文与版本线索；OpenAlex、Semantic Scholar 可补充标识和引文。多个来源去重后保留各自的证据，不要把预印本、录用稿和期刊扩展版当成三个独立创新。现有仓库的 arXiv 采集和本地索引可作为起点。

### 推荐的检索流程

1. 从瓶颈、关键机制、历史术语和失败条件生成少量查询，限制查询数量并保存原文。
2. 同时做 BM25 与向量召回，各取约 100 条；融合排序后，对约 100–200 个候选精排。向量检索必须有独立召回池，不能只对 BM25 已找到的结果重新排序。
3. 围绕有代表性的文献做一至两层真实引文扩展。用于历史评测时，每个新增来源和边的支撑文本都必须在截止时间之前可用。
4. 在相关性合格的候选中，按时期、机制、争议、失败路线和瓶颈覆盖做选择。最后返回证据片段及选择理由。

RRF 可以作为词法与向量排序的低成本融合方法。选择阶段再做 MMR 或覆盖约束的贪心选取，兼顾相关性和去重复。初期不需要训练新的检索模型。

| 可复用项目 | 适合解决什么 | 在本项目中的用法 |
|---|---|---|
| [SPECTER2](https://github.com/allenai/SPECTER2) | 科学论文向量表示 | 作为论文专用编码的参考方案；有合适的外部推理服务时通过 API 使用，并匹配查询与论文 adapter |
| [FlagEmbedding](https://github.com/FlagOpen/FlagEmbedding) | 向量检索与交叉编码器精排 | 将 BGE 系列作为 API 编码和精排的候选方案；无对应托管版本时选经过检索评测的其他 API，不要求本地部署 |
| [GROBID](https://github.com/grobidOrg/grobid) | 解析学术 PDF 结构和参考文献 | 可接解析服务 API，保留段落、引文位置和标识；已有可靠 HTML/XML 时优先直接解析 |
| [PaperQA2](https://github.com/Future-House/paper-qa) | 论文问答、证据查找和带引用的综合 | 借用局部证据检索；回溯评测时接入冻结资料，关闭实时元数据补全 |
| [OpenScholar](https://github.com/AkariAsai/OpenScholar) | 面向科学文献的检索与综合 | 参考其证据综合设计；首轮不复制其大规模数据和训练工程 |

这些工具不会自动保证轨迹完整，也不能直接输出“高质量研究史”。首版采用现有 SQLite 词法索引、API 生成的向量及 API 精排即可；本地保存向量并计算相似度不需要模型推理硬件。上述开源仓库提供可参考的方法与实现，不代表其作者已经提供可用的公共 API，也不要求为了接入它们自建服务。先验证这套检索组合，再决定是否有必要比较更复杂的检索策略。

### 怎样定义高质量与覆盖率

不要用总引用量或顶会标签决定全部 selected data。历史快照中的累计引用若来自今天，会带来未来信息；即使没有泄漏，高被引筛选也容易反复选出主流方法，恰好强化所担心的同质化。

选择依据应是研究问题相关性、方法和证据是否明确、是否补充新的机制或失败信息，以及来源是否可以核验。按“子方向×时期×机制类别”建立覆盖表，保留低关注度路线、失败结果、竞争解释和并行进展。文献未报告失败，不能从低引用或没有后继论文推断它失败了。

用两位熟悉领域的人整理一小组关键文献与关键转折作为覆盖检查集，报告文献召回率、阶段覆盖率、有效证据片段覆盖率和重复率。对没有选中的尾部样本也进行抽查，防止只在已召回结果中自我验证。达到覆盖饱和可以停止扩展，但不能声称完整覆盖整个研究领域。

## 四 构建具有技术含义的研究轨迹图

### 节点表达研究阶段并保留论文证据

历史研究图只记录已经公开的研究及可追溯关系。模拟跃迁产生的候选用普通运行记录保存，始终标记为待验证；不必另建复杂的探索图系统。生成的想法不能直接写回历史图，成为下一轮的“已知事实”。

图节点按原设想表达一个研究阶段，包含该阶段的代表论文、研究问题、任务条件、核心机制、依赖假设、主要实验及限制、未解决瓶颈、公开时间范围和证据片段。这里的“阶段”是某一研究线上的技术状态，不要求整个领域在同一年同步进入一个阶段。

实现时先逐篇抽取贡献记录，再把问题与机制相近的记录整理成阶段节点。贡献记录是阶段节点的证据，不需要新增另一套图模块。阶段内部保留分歧和例外；论文有多个贡献时允许支持多个节点，但保留统一论文 ID，避免统计时重复计数。每次按截止时间重新生成阶段摘要，避免后来论文修改了对早期阶段的解释。

### 历史关系使用有向无环图

令历史图为 `G_T = (V_T, E_T)`。演化边由前驱研究状态指向后继状态，允许分叉、汇合和多父节点。边的关系类型包括继承机制、替换机制、放宽假设、改变目标、跨场景迁移，以及反驳或限定先前结论。

一条边需要回答：后者究竟继承了什么、改变了什么、解决了前者哪个问题，以及证据在哪里。引用关系可以用于发现候选边，但不能自动等同于技术继承。没有足够证据的关系只能标记为可能关联。

不能把神经网络、ResNet、Transformer 强制串成一条替代链。它们并非天然属于同一细分任务中的相邻阶段，不同机制也可以组合或长期并存。一个更可靠的图应允许不同研究线发展后在新贡献处汇合。

每条历史演化边必须由可证实先后的论文贡献支持；后续阶段的代表机制确实承接前驱机制，才能连接。阶段持续时间可能重叠，应依据机制首次出现和继承证据判断先后，不能直接以整个阶段结束日期排序。同日或先后无法判断的工作保留为并行状态，不通过任意排序制造继承。语义相似、同期争论等可记作节点属性，避免破坏演化 DAG 的含义。DAG 表达的是文献中的技术关联，不自动证明历史因果关系。

### 将跃迁幅度 证据置信度与价值分开

“加模块就是小突破，换架构就是大突破”不够稳健。少量改动可能解除关键约束，大幅架构变化也可能没有收益。建议为边保存一个变化向量：

`Δ(u,v) = [问题变化, 假设变化, 核心机制变化, 能力边界变化, 资源条件变化]`

每个维度先采用可解释的序数标注，如无变化、局部变化、关键变化。标注必须有相应片段，不支持的维度记为未知。另存证据强度、关系置信度和分歧，而不是把它们混成一个分数。

边仍保留一个明确的大小，供图展示和 LLM 选择跃迁幅度使用。初版可以按变化向量和证据采用四级标注：1 为原机制内的局部调整；2 为子机制或适用条件的实质改变；3 为关键机制或关键假设的改变；4 为同时改变核心机制与已验证能力边界的变化。未知幅度单独标注，不记作零。四级标准需要各领域提供实例作为锚点；它是待验证的操作化定义，不是已经建立的普适尺度。

对历史边，能力边界变化需要当时已有实验支持；对未来跃迁，模型只能给出目标幅度及理由，不能把预期突破写成已经实现。LLM 同时读取边的等级、变化向量和适用条件，避免把所有相同粗细的边理解为同一种技术动作。边幅度不是成功概率，也不必满足几何距离的对称性或三角不等式，沿路径求和不代表可累加的科学价值。

先按三个领域分层抽样约 150 对历史贡献，由领域标注者判断变化维度与相对幅度，分析一致性、误差和跨子方向稳定性。正式实验保留带权图，并与去权重、打乱权重等版本比较。若权重没有独立收益，应如实缩小贡献声明，继续修订其定义，不能把完整系统的收益直接归功于边的大小。

### 模型应怎样使用图

给 LLM 同时提供阶段级全图摘要和当前跃迁相关的详细证据：前者保留具体小方向的整体发展趋势，后者包括关键路径、未解决限制、矛盾发现和机制适用条件。规模较小时可以直接提供完整阶段图；规模增大后再按问题展开局部细节。图序列化为结构化文本即可，不需要增加 GNN 模块。

强制模型提出可核验的跃迁操作：从哪个瓶颈出发，借用哪个机制，保留哪些约束，改变什么假设，为什么适用于目标问题，又可能在哪个条件下失败。可用操作包括假设移除、机制替换、目标重定义、结构迁移和互补路线组合。

**选择更远的概念只能帮助扩大候选范围，不能证明机制发生了有效迁移。** 跃迁大小应由拟议改动决定，不随轮数机械增大。真正的新 idea 还没有存在于历史图上；系统是在提出一个新的研究假设，而不是走到已知图中隐藏的答案节点。

## 五 模拟反馈与最多四轮探索

### 将 world model 落实为研究过程的条件模拟

保留 world model 这一环节，首版可以使用 LLM 实现研究世界模型：在给定技术假设、研究条件和可用证据下，模拟下一步可能发生什么。这里不需要额外训练一个通用世界模型，也不需要接入与科研推演无关的视频世界模型。论文应准确说明它是基于 LLM 的研究过程模拟，其预测能力需要评测。

每次模拟绑定 LLM 提出的跃迁方向，依次推演：新机制作用于哪个瓶颈、哪些假设必须成立、可能带来什么改善、改善后还会出现什么新限制，以及失败时最可能是什么原因。讨论后形成具体 idea，输出价值和可行性判断，并把关键不确定性交给下一轮。能够做小检查时，可以补充验证；模拟文本与真实测量始终分开保存。

反馈不仅用于修改当前 idea，也可以提供下一跳的出发点。例如，第一轮预测机制 A 能解除瓶颈 X，但会产生瓶颈 Y；第二轮就可以在“A 确实有效”的条件下探索解决 Y 的机制 B。这正是原方案中连续模拟跃迁的作用。后续结论必须保留其依赖假设，不能把第一轮的预测当成事实，再通过几轮自我引用制造确定性。运行记录保存这些条件即可，不需要额外建立一个生成图模块。

同时区分三种预测：未来是否出现相关研究、给定实验是否成功、成功后是否有使用价值。不要让模型输出一个含义不清的“idea 价值 0.92”。只有在独立开发数据上检验过的预测器才输出解释清楚的概率；初版可以报告等级和理由，并标记尚未校准。

### 如何避免讨论压低探索能力

提出者和批评者先独立阅读同一证据包，再进行一次针对关键分歧的回应。分角色可以由顺序调用实现，首轮不需要部署大型多代理系统。批评的作用是定位可验证分歧，而不是以投票决定科学真伪。

建议将异议分为三个层次。

| 异议 | 处理方式 |
|---|---|
| 可核验的矛盾或协议错误 | 记录证据，暂停相应实现并要求修订；不要抹掉候选和原判断 |
| 关键前提未知或证据不足 | 产生待检验假设，优先安排有信息量的小检查 |
| “不常见”“不像好论文”等偏好判断 | 保留为弱意见，不能单独否决候选 |

保存批评前的候选和每次修改，检查讨论是否把不同机制都改写成同一种保守方案。低支持但可检验的方向不应仅因不熟悉而被排除。创新性、可行性和价值分别比较，综合判断时保留每个维度的理由。

如果使用批评权重，首轮可在开发集比较 0、低权重、强权重三档，固定后再跑测试集。权重不是越低越好；要观察错误过滤率、有效新颖候选误杀率和实际效用之间的关系。为估计误杀，独立抽查一部分被批评淘汰的候选，而不是只评价存活者。相关的知识依据与多视角评价设计可参考 [InnoEval](https://arxiv.org/abs/2602.14367)，但其评价分数仍需独立验证。

### 四轮是整个任务的预算上限

定义一轮为“提出一个候选或明确修订—条件模拟与批评—必要的小检查—更新决策”。**一个任务全局最多四轮**，分支共用计数。文献调用、重试、额外草稿和检查也记录成本，避免隐藏大量 best-of-N 采样。

第一轮提出最有依据的机制变化；后续根据反馈选择修订、切换机制或停止，不强制远跳。停止可以有三种理由：已有建议达到预设的投入标准，连续探索未形成实质改进，或者轮数耗尽。达到投入标准只意味着值得开展下一步研究。

首版使用简单、预先确定的停止规则：若候选机制明确、相对已有研究有实质差别、价值说明具体、可行性达到开发集设定的标准，且没有尚未处理的关键反驳，就可以提前输出。若未达到标准，依据失败原因继续；若连续两次相邻轮次比较都没有形成实质改善或机制变化，可以以“仍需研究”状态结束，这至少需要三轮记录；第四轮必须结束。阈值只在开发集确定，不能针对测试题改动。

这保留了“前面已经很好就不再过度探索”的原意。还必须检查提前停止是否错过更好的方向：在独立评测子集上继续跑到第四轮，将后续收益作为停止策略的诊断结果，不反馈给正常生成过程。无需在初版引入价值信息估计或新的学习控制器。

最终从已经产生的候选中选择依据最充分的一个，不默认最后一轮一定最好。输出主 idea、问题、机制、与最近工作的区别、价值成立的条件、实验方案、资源需求、不确定性和停止理由。可行性建议采用“值得小规模验证、需要补证据、当前不建议投入”三种状态。

## 六 最终输出应当让研究者能够判断是否值得做

一个合格的结果不只包含题目和一段摘要。建议统一输出以下内容，使不同方法可以在相同格式下比较。

| 内容 | 必须回答的问题 |
|---|---|
| 研究问题 | 具体想解决哪个未解决瓶颈 |
| 跃迁依据 | 来自图中哪些发展阶段，改变了什么机制或假设 |
| 方法设想 | 新机制怎样工作，与最近方法有什么实质区别 |
| 研究价值 | 如果成立，将改善哪个问题，对谁有意义，在哪些条件下有意义 |
| 可行性 | 需要哪些技术、数据与实验条件，哪些已具备，哪些可以后续补齐 |
| 模拟判断 | 预期结果、失败方式和竞争解释分别是什么 |
| 验证建议 | 最小的可检验实验是什么，什么结果会削弱这个 idea |
| 不确定性 | 哪些判断有文献依据，哪些仍是 world model 的预测 |

研究价值可以先分为问题重要性、机制新颖性和预期改善程度三项，另外报告可行性。保留各项理由比只给总分更有用。若需要总分用于选择，权重和评分标准必须固定，并用独立评价检查其排序是否合理。

## 七 PaperFutureBench 怎样测到未来预测能力

### 保留用过去论文预测后续论文的核心设定

可以借鉴 FutureBench 的时间约束和事后验证思想：在某个时点固定可用信息与预测，再用后来出现的结果判断预测。这里参考的是 Hugging Face 的 [FutureBench](https://huggingface.co/blog/futurebench)；它面向未来事件预测，不能直接替代科研 idea 的机制与价值评价。PaperFutureBench 需要自行定义什么算作一个新研究贡献，以及怎样判断预测与贡献对应。

一个任务由“领域中的具体问题、截止时间 T、T 之前可获得的论文与条件”构成。系统输出一个主 idea，评价端再判断它是否对应 `(T, T+H]` 内首次公开的相关研究。任务描述和 selected data 都从历史资料产生，不能先看到未来论文，再把其独特问题、方法暗示或完整参考文献表反向写进输入。后者可以作为条件重建实验，但不属于这里的开放未来预测。

未来通常有多个合理方向，因此每个任务对应一个后续贡献集合，不强行指定唯一标准答案。对同一论文的预印本、录用版和扩展版做关联，对同一技术贡献做去重；一篇论文出现于多个场合不能带来多次命中奖励。

### TMLR 与 ICLR 2026 怎样使用

保留 TMLR 2026 和 ICLR 2026 作为重点目标集，但按贡献首次公开时间划分过去与未来。假设某篇 ICLR 2026 论文在 2025 年 5 月已有预印本，那么对截止时间为 2025 年 6 月的任务，它已经是历史，不能再作为预测命中。TMLR 2026 录用稿也可能早已有公开版本；期刊年度不能保证内容新鲜。

一个可操作的回溯配置是：`T = 2025-06-30`，预测窗口为 `2025-07-01` 至 `2026-06-30`，按截至 2026 年 10 月 12 日可核实的公开记录整理目标集，并标记其中属于 ICLR 2026 或 TMLR 2026 的论文。这个配置只是起点，最终 T 必须与实际能通过 API 调用且可核验的历史模型版本相匹配。更早时间的任务可以形成开发集；测试任务按时间及研究线隔离，避免围绕同一篇未来论文反复调参。

TMLR 是滚动投稿的期刊，官方评审原则也不将主观的影响力预判作为唯一接收依据。因此，TMLR 录用可以证明一定的评审筛选，不能直接等同于高价值突破。[TMLR 官方说明](https://jmlr.org/tmlr/)

三领域不一定在这两个来源中均匀出现。AI4EDA 应同时整理 DAC、ICCAD、DATE 等领域会议及相关公开预印本；第一个交叉领域也需要覆盖相关视觉、机器学习和解释性论文。最终保留统一的“ICLR/TMLR 子集”便于比较，另报告三个领域各自的完整目标池，避免因目标池过窄而把领域里已经发生的创新误判为未命中。目标池内的来源和贡献类型要分层报告，不能把所有发表信号揉成一个质量分。

### 时间隔离必须覆盖整条调用链

仅将检索限定为 T 之前，不足以证明模型没有见过答案。下面这些位置都可能把未来信息带回预测端。

| 位置 | 需要固定什么 |
|---|---|
| 论文内容 | 最早可核实的公开日期、T 时可用的具体版本、版本文件与文本哈希；不能用旧的创建日期搭配今天的摘要或修订稿 |
| 文献发现与选择 | 历史论文清单、检索查询与返回记录；不按今天的引用量、后来的获奖或录用结果选择历史输入 |
| 图节点和边 | 支撑每个阶段和关系的来源都在 T 前；图摘要、边权重和语料统计量也只由允许的材料产生 |
| 所有模型调用 | 生成、抽取、向量化、精排、world model、critic 使用可识别版本；现代辅助模型也可能泄漏未来机制 |
| 外部工具 | 回溯生成阶段只访问冻结资料；实时搜索不能通过标题建议、摘要补全或相关推荐引入 T 后内容 |
| 评价端 | 后续论文、专家标签与评审结果只供评价使用，不回流到测试题的构图、提示词和停止阈值调整 |

模型的“发布日期早于论文录用日”这个条件仍然太弱。理想条件是生成端及其辅助模型的可核验固定版本在 T 前已经存在，目标贡献在 T 后首次公开；同时保存 API 的模型标识、服务版本或可获得的版本证明。公开的知识截止说明可以作为依据，但不等于完整的训练数据审计。即使满足这些条件，也应报告无法排除的非公开信息风险，而不是承诺绝对无污染。

API 方案不要求自己部署旧模型。应先确认服务是否提供真正固定的历史版本；服务商今天仍沿用的同名模型、会变化的 `latest` 别名，不能当作版本冻结证明。如果无法通过 API 获得足够可核验的旧版本，仍然可以运行回溯实验，但应明确称为“文献时间受限的回溯评测”，不能把其高分单独当成预测未来的证据。

因此建议同时建立两类互补证据：可核验历史版本用于回溯比较；最新 API 模型用于从实际生成日期开始的前瞻预测。前瞻实验在生成后固定输入、输出、模型配置和时间证明，再等待后续论文出现。若实际在 2026 年 10 月 12 日开始，可预先设置三个月和六个月窗口；这是待开展实验，不能写成已经完成的验证，也无法在未来一个月内得到完整结果。

### 主要指标要同时约束新颖性与机制对应

建议以“新颖的未来贡献命中率”作为主指标。对每个任务，最终主 idea 只有同时满足以下条件才计为命中：其核心贡献在 T 前的资料中尚未成立；它与未来目标贡献在研究问题和关键机制上实质对应；预测写出了足以区分一般趋势的技术内容。仅猜中“代理更安全”“解释更可信”“电路更高效”不计分。

可以记为：

`NovelFutureHit@1 = 有新颖且机制级命中的任务数 / 全部测试任务数`

新颖性核验使用历史资料；未来匹配使用后续资料，两个判断分别记录。目标论文若只是重新描述已有机制，不能让系统凭复述旧工作获得“新颖预测”分。若某方法没有输出有效 idea，该任务计为未命中，并另外报告输出失败率，不能将其从分母删掉。

主任务每次只提交一个主 idea，避免方法靠列出大量模糊建议碰中答案。如果补充报告 top-3，则所有方法都使用相同输出数量与总调用预算；同义候选和同一未来贡献只计一次，不能把四轮草稿都作为独立免费预测。

未来论文匹配采用两步：先从冻结的后续目标池召回可能相关的贡献，再按固定标准核验“问题、机制、作用条件”是否对应。保留支持与反对片段；在开发集上用人工判断校准自动评价，并抽查未召回样本。评价模型不知道系统名称、作者和录用级别，尽量避免依据写作风格和声望打分。

| 指标 | 回答的问题 | 不能据此推断什么 |
|---|---|---|
| 新颖未来贡献命中率 | 是否提出后来出现、且当时尚未成立的具体研究机制 | 不证明系统实际做成了研究，也不证明未命中 idea 无价值 |
| 历史重复率 | 有多少候选只是已有工作的改写 | 低重复率本身不证明方法可行 |
| 机制多样性 | 不同任务或重复运行是否持续落在相同机制与假设上 | 主题距离远不等于有意义的创新 |
| 独立价值与可行性评价 | idea 是否解决真实瓶颈，假设是否可检验，验证条件是否合理 | 评价者的意见不能替代实际实验结果 |
| 讨论前后有效候选保留率 | world model 和 critic 是否修正错误，同时保留有效的新颖方向 | critic 自己给出的高分不能充当独立验证 |
| 平均轮数与 API 成本 | 动态停止是否节省调用，同时保持质量 | 更早停止本身不代表方法更好 |

专家评价作为价值判断的补充，可以先对分层抽样进行双盲成对比较，分别评新颖性、重要性、机制合理性和可行性；报告分歧，不把四项未经验证地合成唯一金标准。三个领域分别汇总，再计算等权宏平均，避免文献量最大的领域支配最终结论。

统计上按任务配对比较，报告效果差和置信区间。来自同一研究线或同一论文家族的样本具有相关性，应按这些单位分组抽样；多次随机运行用于估计波动，不能冒充更多独立研究问题。开发集确定匹配阈值、讨论权重和停止规则，测试集冻结后只按既定流程评价。

## 八 哪些对照才能证明原方案有效

比较首先回答三个问题：发展图是否比同样的论文更有帮助；跃迁大小是否真正影响探索；world model 是否在保留创新的同时提高价值判断。所有方法使用相同模型版本、历史边界、最终输出格式和总调用上限。

### 主实验配置

| 方法 | 具体配置 | 比较目的 |
|---|---|---|
| 文献 RAG 直接构思 | 同样的 selected data，直接生成一个 idea | 确定基础水平 |
| 文献 RAG 多候选选择 | 同样的资料与总调用预算，独立构思后选择最佳候选 | 排除增益仅来自多次采样和筛选 |
| 发展链构思 | 用同样的资料组织时间发展链，可参考 Chain of Ideas | 检验分叉和汇合是否比线性轨迹有效 |
| PaperFuture 无权重版本 | 阶段、关系、证据不变，隐藏跃迁幅度及其对应提示 | 检验权重及幅度信息的增益 |
| PaperFuture 固定四轮 | 完整带权图与 world model，每个任务固定四轮 | 作为质量和成本的参照 |
| PaperFuture 动态轮数 | 完整方法，最多四轮，满足既定条件提前停止 | 检验最终系统表现 |

主实验可以从以上六组起步。最接近的完整系统还应选择一个可复现基线，例如 [FlowPIE 官方实现](https://github.com/AIforIP/FlowPIE)。接入前核对数据和运行条件是否齐全；复用了其思想但改动了数据、模型或流程时，应写成适配版本，不能宣称复现了论文报告的原始数字。Graphs of Research 包含训练环节，其原始训练结果与本项目 API 直接调用设置不同；可以比较其图表示思想或公开系统，但要分别报告训练与推理差异，不能把这种差异归功于本方法。

需要做两种公平比较。第一种固定同一批 selected data 和上下文长度，研究图与 world model 本身的作用；第二种让各自的检索流程完整运行，比较端到端效果，同时报告获取文献和构图的成本。否则无法知道提升来自方法，还是只是读了更多论文。

### 围绕现有环节做消融

跃迁权重至少比较真实权重、统一权重和打乱权重。打乱时保留节点、时间方向与图拓扑，只置换幅度，避免无意引入其他变化；幅度向量若仍留在提示中，无权重实验就不成立。再将图转为同样长度的时间顺序摘要，检查“图”的作用是否只是提供了更完整的文字背景。

world model 比较无模拟反馈、单次模拟反馈、模拟加结构化讨论。讨论权重在开发集比较零、低、强三档，观察纠错与新颖候选保留之间的变化；保留未经过讨论的原稿，防止只凭最终文本判断探索能力。这里是在细化原有 world model 环节，不另设独立研究系统。

动态停止比较固定一轮、两轮、四轮和最多四轮的自适应版本，画出质量随实际 API 成本的变化。停止策略需要达到预先声明的质量容忍范围，再比较节省比例；仅仅看到差异不显著，不能断言两者质量相同。对提前停止的抽样任务继续跑四轮，用于分析漏失的有效改进。

图本身也要检查正确性：阶段摘要是否准确，边是否有继承证据，幅度排序能否得到领域判断支持。若这些表示错误很多，最终 idea 偶尔命中也不能证明系统学到了发展规律。

### 后续真实验证的角色

后续资源到位后，可以从各领域选择少量具有代表性的 idea 开展真实研究验证：解释性方向检查可观测证据与解释是否一致，安全方向检查攻击与正常任务表现，AI4EDA 检查功能正确性及相同约束下的设计收益。实验具体内容由生成的 idea 决定，不预先强行指定一种新算法作为 PaperFuture 的输出。

这些验证有助于说明预测不止停留在文字层面，但不要求 PaperFuture 自己训练模型或执行完整电路设计。若只有 API 模拟结果，论文就报告模拟和预测层面的证据；实际实验收益必须来自真实运行，不能由 world model 推演代替。

## 九 现有代码怎样沿原方案改进

仓库已经具备可复用的论文索引、研究状态、轨迹恢复、idea 生成、模拟与批评、运行记录和测试。最合理的实现路线是修正这些环节的语义与连接方式，让实际执行路径与论文方法一致，而不是另写一套研究代理平台。

### 当前实现与目标的主要差距

| 现有位置 | 审查发现 | 对应修改 |
|---|---|---|
| [harvest_arxiv.py](../scripts/literature/harvest_arxiv.py) 的 `store` | 同 ID 记录删除后重写，没有保留完整的不可变版本历史 | 为论文版本分别保存内容、公开时间和哈希；构建指定 T 的资料清单，避免旧日期搭配新版摘要 |
| [localindex.py](../src/farfield/services/localindex.py) 与 [serve_index.py](../scripts/literature/serve_index.py) | 有 BM25 和候选精排；向量模式在 BM25 候选内排序。`related` 以词法相关近似关联，不等于真实引文 | 增加独立的 API 向量召回，与 BM25 融合；把真实参考文献关系和相似论文结果分开；`search/get/related` 统一受快照约束 |
| [researchspace.py](../src/farfield/extras/researchspace.py) 的 `ResearchState`、`TrajectoryStep`、`recover_trajectories` | 已有问题、机制、假设和局限字段；当前分组主要依赖引用或局限性词汇匹配，再整理成轨迹 | 复用这些抽取字段，按阶段组织节点，保存分叉、汇合、关系证据和跃迁权重，避免把相关论文强行压成单链 |
| [embed.py](../src/farfield/extras/embed.py) | 当前为 64 维哈希 TF-IDF 加固定随机投影，表达词法距离 | 保留为可重复的简单基线；正式检索接 API 向量表示；两者都不能直接充当技术跃迁幅度 |
| [remote.py](../src/farfield/extras/openworld/remote.py) 的 `ConceptSpaceSearch` | 从概念空间选取中远距离候选，主要依赖标题词法距离与图度数；默认解析注册表中的 `full_graph` | 正式回溯只允许加载指定历史快照；返回可迁移机制、适用条件与文献证据，再交给 LLM 决定跃迁方向和幅度 |
| [ideation.py](../src/farfield/extras/openworld/ideation.py) | 已有独立的 idea、research-world rollout 和 critic 调用 | 沿用模型客户端，将阶段图、边变化与证据接入提示；明确当前候选的机制操作，以及下一轮依赖的模拟条件 |
| [discovery.py](../src/farfield/extras/openworld/discovery.py) | 默认每条 lineage 最多四跳，最多三条 lineage、八个 idea；有前景后还可能分支 | 加入任务级四轮上限，让所有分支共用计数；按既定标准提前停止，输出已有候选中的最佳结果 |
| [timeslice.py](../src/farfield/timeslice.py) 与生产检索路径 | 已有截断图和历史评测保护，但没有统一覆盖上述概念检索入口 | 将日期和快照校验放到共同数据入口；评价端可以看到未来资料，生成端不能 |

这里的修改分别对应原流程中的文献、图、跃迁、world model 和停止，不构成额外方法模块。正式运行还应集中记录 API 版本、请求、返回、token、费用和失败重试；这些是可复现的实现要求，不需要独立包装成论文贡献。

### 正式回溯前必须修正的具体问题

对当前随仓库提供的 `attn-concepts-s1` 执行 `ConceptSpaceSearch._resolve_graph()`，实际返回 `concepts/attn-concepts-s1/G_full.json`。这张图声明 `T = 2017`，共有 1,654 个节点，其中 80 个节点的年份大于 2017。这说明该路径不能直接当作只使用 T 前信息的预测器。

影响不只在于是否最终抽中了未来节点：当前向量构建会遍历加载的节点，未来节点还可能改变词频统计和距离排序。因此必须先裁定可用资料，再构图、计算统计量和检索；在输出阶段删掉未来标题并不足够。这个发现是对执行路径的检查，不意味着已经证明任何尚未开展的论文实验存在污染。

`localindex.py` 的日期参数是可选的，`get` 入口也没有同样的时间限制。历史模式应绑定一个必须携带的快照标识，从底层拒绝读取快照之外的论文版本，而不是依赖每个调用者都记得传 `before`。`related` 即使过滤了返回论文，也不能先读取一篇未来论文作为查询来源。

目前的轨迹辅助函数还存在按轮次使用 early、middle、far 的约定，它与概念空间检索是不同路径。需要统一正式入口，让跃迁幅度由机制变化与反馈决定；不要把辅助路径的存在误写成完整系统已经实现了带权技术跃迁。

仓库已经对模拟结果使用 `GENERATED` 和 `research_world_simulation_not_evidence` 之类的标识，这一点应保留。后续需要验证的是模拟结果是否有预测能力，而不是再增加一个听起来更复杂的 world model 名称。

### 最小的数据约定

为了让各环节准确对接，可以在已有记录结构上补充以下字段。字段名称可以随代码习惯调整，语义必须保持清楚。

```text
论文证据
  paper_id, version_id, first_public_at, version_public_at,
  source_url, content_hash, evidence_spans, snapshot_id

研究阶段节点
  stage_id, problem, conditions, mechanisms, assumptions,
  demonstrated_capabilities, limitations, paper_ids, evidence_spans

阶段演化边
  from_stage, to_stage, relation, change_vector,
  leap_weight, confidence, evidence_spans

每轮模拟记录
  round_id, source_stages, proposed_change, target_leap_weight,
  inherited_hypotheses, world_model_forecast, objections,
  value_assessment, feasibility, next_action, stop_reason
```

`leap_weight` 是历史变化幅度，`target_leap_weight` 是未来候选的目标幅度；`confidence` 是当前证据支持程度，不混用。条件预测和真实测量分开存储。历史阶段与候选之间的关联引用已有 ID 即可，无需引入额外图数据库或复杂状态平台。

### 首先补哪些验证

最有价值的工程测试是能阻止研究结论失真的测试：所有读取路径都拒绝未来版本；缺失指定快照时明确失败；改变未来数据不会影响历史检索结果；全部分支加起来不超过四轮；达到停止条件后不再隐含生成额外候选；模拟文本不能转成文献证据；API 配置与实际返回版本不符时明确记录异常。

这些测试验证流程约束。带权图有没有用、world model 会不会压低新颖性，必须由第七和第八节的研究实验回答，不能靠单元测试数量证明。

## 十 API 方案的执行顺序与规模

当前工作的资源重点是论文 API 的配额、模型调用、缓存与存储，以及领域核验时间。模型大小不是本地部署约束；可以通过 API 比较多个模型，但首先固定一个端到端配置，避免同时改动模型、文献和提示后无法归因。批量抽取、向量化和图构建结果按模型版本与输入哈希缓存；候选推演仍保留独立运行记录。

建议先做一个月的验证阶段，目标是建立可靠的完整实验链路，不把“一个月内完成”预设成高质量论文必然可行的承诺。

| 阶段 | 工作范围 | 可以检查的交付物 |
|---|---|---|
| 第 1 周 | 三领域各明确若干研究线；确认历史 API 版本可用性；修正论文版本与统一时间入口 | 领域边界、冻结资料清单、可执行的时间隔离检查 |
| 第 2 周 | 运行混合检索与阶段抽取；标注一批边；接入整体轨迹和局部证据 | 三领域的样例发展图、边权重依据、检索覆盖检查 |
| 第 3 周 | 接通跃迁与 world model；落实全局最多四轮；在开发集确定讨论权重和停止规则 | 三领域端到端运行记录，以及对每轮作用的分析 |
| 第 4 周 | 冻结配置；运行主对照和核心消融；人工复核部分命中与淘汰候选 | 可重放的评测结果、误差案例、下一阶段正式实验配置 |

API 联调阶段可先用三个领域各两个任务确认链路，随后用每个领域约十个开发任务做先导实验。三十个任务适合发现流程问题和估计效果波动，不能据此默认已获得足够的跨领域统计证据。正式测试集另行冻结，其规模应根据任务相关性、效果差和方差调整；资源补齐后优先增加独立研究线、时间切片与人工核验，再增加重复采样。

以三十个任务、六种方法、两次独立运行为例，共 360 次系统运行。按照细化设计中的默认配置，每轮一次跃迁生成，加上条件模拟、独立评议和综合判断三次调用，最多四轮，共最多十六次核心调用；将该上限统一用于规划，得到 5,760 次核心调用。这是规划估算，尚未包括文献抽取、图构建、评测和重试；不同基线的实际调用结构及提前停止会改变用量，应以运行日志结算。

费用按各 API 实际单价和使用量计算，分别报告一次性文献处理成本、每次预测成本和评测成本。不要把构图费用全部隐藏在预处理，也不要让每次任务重复付出相同的全文抽取费用。当前方案不要求购置或预留 GPU。

论文主结果至少应回答：在三领域是否均有收益，边幅度是否有独立作用，讨论是否保留了有效的新颖方向，以及动态停止是否在质量容忍范围内节省调用。若先导结果未支持某个假设，应优先分析节点、边和反馈的错误，而不是通过增加模块掩盖问题。
