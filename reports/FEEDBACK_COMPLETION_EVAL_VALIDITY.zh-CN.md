# 分项反馈与科研评测效度

日期：2026-10-09。最近一个月的文献窗口为 2026-09-09 至 2026-10-09。

当前 SciFact 评测适合作为工程诊断与证据研究的局部测试，不能承担“通用自主科研系统优于自由 agent”的主结论。本轮补齐原生分项反馈、实际干预检查、任务交付条件，并用保存的真实程序验证。科学解释是否正确和新想法是否有价值，仍须由额外的独立实验检验。

## 为什么现在的分数不够

1. **测量对象偏窄。** 四个公开开发集 claim、两个任务包测的是检索、标签和证据句，未覆盖从模糊目标形成问题、建设工具、提出方法、实施实验的长程能力。
2. **已经成为开发数据。** 多轮修复都读取了相同题目和结果，后续提升不能视为未见任务泛化。公开题还存在无法排除的预训练污染；新抽取 ID 不等于模型没见过。
3. **总分不能诊断机制。** 本次真实错误就是把证据句错误归因为检索错误。多个组件共同变化时，分数上升也无法定位原因。
4. **对照只能回答有限问题。** 同模型、同工具、同预算上限是必要条件，但两臂共享执行服务和原生评分路径，主要比较规划／结果回应策略的增量，不能估计所有执行保护的总收益。
5. **样本、重复与预算跨度不足。** 单模型、两组题、每臂最多四次请求，没有足够独立任务或重复运行，且真实消耗差异大。一次超时也会主导结果。相同调用次数不能替代成本—质量曲线。
6. **分母会误导。** 可评分提交不是有信息量的科学实验。只统计成功运行的 F1 会遗漏交付失败；只算每次提交的成本会奖励重复提交；只数错误 claim 则可能奖励什么也不说。

因此应保留这套测试作回归，不继续用它挑选系统总体设计。未提交应保留为缺失科学测量，同时在“到预算仍未交付”的任务失败率中计入分母；不能删除失败，也不能把失败伪装成真实测得零分。

OSWorld-Science 的错误分析尤其相关：产物可在不同格式之间自洽转换，却仍继承最初的科学解释错误。这里可借鉴的是独立来源核验，而非增加同源自检次数。[原文案例](https://arxiv.org/html/2609.39903v1#S4)

另有三项相关补充，但不能冒充近一个月首发论文：

- [AgentIdeaBench](https://github.com/HKUST-KnowComp/AgentIdeaBench)：论文 9 月 7 日，代码 9 月 11 日发布。Static／Active／Replay 对照把“获得了什么资料”与“跨轮主动获取资料的过程”分开。可借其控制方式；其 critic 分数不替代真实实施与机制验证。
- [TruthInsightBench](https://arxiv.org/html/2609.05079v1)：9 月 4 日。关注执行产物、控制实验、稳健性和可证伪性，但采用单个固定 LLM judge，专家校准仍列为后续工作。“固定评委、确定性聚合”不等于独立可信评价。
- [Terminal-Bench-Science](https://www.terminal-bench-science.ai/announcement)：8 月 27 日发布。专家贡献的科研工作流，以具体产物和任务测试验收，并报告重复试验与成本—成功率。它更适合作为下一阶段可执行主任务源；不是最新一个月新论文，也不等价于开放科学发现。

以上是方法调研，不是对所有新论文的穷尽检索，也没有照搬各榜单排名来推断 FarField 的表现。

## 本轮落地

### 可定位的原生反馈

SciFact 适配器保留原有两个指标，并补充文档身份 F1、文档＋标签 F1、证据句选择 F1。前者是宿主按文档身份计算的诊断指标，后四项使用上游 metric 实现；不将新增指标称为官方总分。指标携带阶段、定义、适用对象和限制，包括摘要级评分只使用前三个证据句。

通用服务通过 `metric_feedback` 返回冻结定义及数值。总分零不再是唯一可见信息，但这些反馈仍不能自动判断任意领域的错误原因。

### 干预是否真正发生

宿主评价器可注册 `observables`，由隔离评价进程从实际提交独立计算，并写入 `observations.json`。本次观测为论文身份、标签、证据句。模型自己写的同名文件不进入这个可信输出。

程序执行前可声明：

```json
{
  "compare_to": "previous_evaluation_id",
  "intervention": {
    "target_observables": ["rationales"],
    "invariant_observables": ["documents", "labels"],
    "prediction": "改变证据句，保持论文及标签不变"
  }
}
```

只有同一冻结评价合同、有效基准结果和实际观测齐全时才进行核对：目标未变为 `not_observed`，控制量变化为 `confounded`，目标均变化且控制量保持为 `observed_as_registered`。缺少定义或观测为 `unassessed`。所有状态都保留 `mechanism_support: not_assessed`；通过操纵检查只说明测得指定改变，未排除未测混杂，也未证明科学机制。

观测文件摘要参与恢复时的完整性复查，失效结果仍通过现有依赖撤回路径传播。

### 交付与确认的完成条件

`NativeEvaluator.delivery_policy` 由宿主冻结，可指定最低／最高指标及是否达到后停止。空阈值明确表示“交付一个可独立评价的有效提交”，零分也可能完成该交付；它不表示方法性能达标。若任务要求某一性能水平，必须事前设置阈值。

`task_complete` 与原有 `research_complete` 分开；最后一次失败或被撤回的提交不能借用以前最佳成绩宣布交付完成。原有科学证据门槛保留，原生分数不会自动确认假设。宿主要求达到交付条件后停止时，不再继续消耗模型请求。

### 上下文与连续调度

开放程序且没有已注册世界接口时，不再前置全部正式实验协议和创新叙事。提示中完全重复的程序、记忆观测和合同改用明确引用；当前结果包、负结果、撤回及其 digest 完整保留，事件日志不变。不对过去结果做未经验证的模型摘要。

完整轨迹复跑还暴露一个 IDEATE 停滞键问题：科学门槛没有改变时，新的真实观测仍被当成重复情境。修复后，停滞键纳入实际反馈身份；相同拒绝与单纯重试不会重置限制。

本轮使用上轮 SciFact 的录制程序，运行完整生产控制器、开放执行、干净重跑、原生评价与反馈，不调用 LLM 来裁判或生成新答案。第一次复跑停在第四阶段；修复上述调度问题后重新从头运行。

## 新一轮真实模型对照：仍未显示优势

冻结当前代码、评价器、接口与依赖后，用 `gemini-3.8-flash` 重新运行两组配对。case-1 为 claim 742、129，case-2 为 232、298；均为此前按固定哈希抽取、现在已经反复使用的开发题。每臂最多四次 HTTP 请求，使用相同开放程序工具和独立评价器。两组交错安排先后顺序，不重跑替换超时。

| 任务 | 系统 | 最后提交 | 摘要／证据句 F1 | 已返回请求的总 token | 墙钟秒 |
|---|---|---|---|---:|---:|
| case-1 | direct | 有效 | 1.000／0.571 | 26,019 | 35.3 |
| case-1 | FarField | 超时前未提交 | 缺失 | 22,423 | 165.2 |
| case-2 | direct | 超时前未提交 | 缺失 | 13,665 | 126.3 |
| case-2 | FarField | 原生评价拒绝 | 缺失 | 61,279 | 113.9 |

共 15 次 HTTP 尝试，13 次返回、2 次超时；有记录的总 token 为 123,386。超时可能产生的账单未知，因此这些数字不是完整付费成本。每臂 4 次请求、200,000 个已报告 token 的上限并不等价于实际等成本。供应商返回的部分 completion token 数还超过请求中的名义上限，不能把名义限制当作精确账单。运行过程中冻结源文件未改变。[汇总和逐臂原始记录](../docs/audits/2026-10-09-feedback-validity/summary.json)

FarField case-2 的程序能执行，但提交了超出文档范围的证据句索引。独立评价器返回 `invalid_sentence_index`，没有制造零分或接受无效结果。随后生成的结果回应缺少必要的 `measurement_assessment`，下一步修复未在预算内执行。direct 两组也各出现一次不合法 JSON 回复。这些是实际交付与恢复能力的问题，不能全部归为模型基础科研知识不足。

本轮证明了检查能揭露部分失败，**没有证明 FarField 更能解决任务，也没有证明上下文修改降低了成本**。四个开发 claim、两组配对和一个模型不足以估计稳定胜率；上下文、反馈同时修改，跨轮分数变化也不能作单组件因果归因。两臂共享执行服务，只能比较该公共基础之上的增量。

完整系统继续暴露三项优先工作：

1. **缩短修复路径。** 将错误定位到具体结果、字段和允许范围；在生成前展示与当前结果相符的最小回应要求。无需科学主张的接口修复不应承担整套科学叙事，但不能代填模型对结果的解释或绕过撤回义务。本轮没有取消现有门槛，仍需独立验证这些门槛的收益与成本。
2. **控制历史增长。** 本轮仅删除完全重复内容。录制四阶段的后续输入仍达到约 10.8 万字符，说明旧轨迹和学习视图仍显著膨胀。下一轮应按未回应结果、当前决策依赖和可取回原始事件组织上下文，测试负结果与撤回信息是否仍被正确使用；不能先截断再观察分数。
3. **扩大可执行任务边界。** 当前适配器只接入离线 CPU Python 和平面文件，不足以覆盖真实项目、容器、训练和科研原生工具。接入外部完整工作流后再检验 OpenWorld 和远跳，否则再精细的过程指标也不能填补缺失的行动空间。

最终工程验证：主套件运行 2,389 项，65 项跳过、无失败；实际 namespace 环境的 107 项受影响测试全部通过；另有 30 项契约与 180 项回归测试通过。曾误将使用相同固定临时目录的测试套件同时启动，发生文件清理竞争；分开顺序运行后通过，未将该次失败删除或包装为产品性能问题。日志保存在 [verification](../docs/audits/2026-10-09-feedback-validity/verification)。测试通过说明限定路径契约成立，不保证任意研究测量正确。

## 正式评测应如何组织

下面是根据上述资料和本轮代码审计提出的方案，尚不是已经完成的正式实验。

**第一层：真实工作流的端到端交付。** 优先接入 Terminal-Bench-Science 固定发布版的原生环境与评价器，按领域及资源需求事前分层抽题。共同最小隔离环境、同模型、同工具、同模型设置、相同预算上限；额外前沿知识模型若参与，也须给对照相同访问权并计入成本。隐藏参考答案和评价实现，核验 oracle 在本机可复现。不能把容器任务改成现成四选一或 Python 小配方后仍报告原榜单分数。目前 FarField 尚没有完整 Harbor／任意项目工作目录适配，因此这一步仍需工程接入。

**第二层：问题形成与长程行为。** 在同一研究目标和独立验收标准下，交叉比较自然简报／充分方法指导、短程子任务／完整工作流。路径只对评价者可见；不给 agent 解题图。两种输入的差异只涉及方法提示，不能删除用途、数据定义和必要的硬约束。先用少量开发任务核查规则是否接受等价正确实现，再冻结正式任务，避免靠模糊题面制造失败。

**第三层：OpenWorld 与远跳的机制增量。** 在完整 FarField、去掉 OpenWorld 的版本、去掉远跳的版本和自由 agent 之间作同预算消融。OpenWorld 保存实验前预测、真实结果和后续选择，分开计算覆盖率、预测误差与实际实验收益；允许有依据地维持判断。远跳比较局部、普通跨域、技术脉络／机制引导策略，开放实际实现、控制候选数和计算预算。有效方法数、独立验证表现及成本为主要结果；概念距离、故事宏大、critic 投票和行动次数不当作收益。

再加共享观测的对照：向不同控制器提供同一批实际观测，检验结果使用；另做自由探索，检验获取何种观测。两者不可混在一起，否则无法区分“找到了好材料”与“更会使用材料”。对远跳，技术来源需要文献核验，性能需要隐藏评价，机制需要操作核验和独立对照，新颖性不能由“检索没找到”自动宣告。

**必须同时报告的指标：**

- 任务交付率及全部失败类型；可评分结果上的原生质量，另报告全任务口径。
- 预先抽样审计的无依据／错误科学主张比例，以及应回答内容的覆盖率，避免沉默得高分。
- 测量有效的执行次数与成本；有区分能力的实验另算，不把重复提交当新信息，也不只奖励正结果。
- 实际无效干预率、错误归因率、被撤回依据的继续使用率；方法性能与机制支持分开。
- 总 token、HTTP 尝试、CPU/GPU 时间、墙钟时间及可归因账单；超时账单不明则标未知。
- 预算—质量曲线、重复失败恢复与长程完成率。比较多个预算点，不能只挑一个最有利的调用上限。

开发诊断先取 6–12 个跨领域任务，每题至少三次独立模型运行以估计方差。正式规模依据预先规定的最小有意义收益和配对方差确定，再锁定未用于修改系统的任务；任务或原研究是统计单位，重跑与种子不是新任务。报告按任务聚类的不确定性，保留超时和失败；技术故障重跑按统一事前规则执行，两臂对称，不用重跑替换原失败。机制消融多重比较须预先限定，不能事后从大量指标挑成功项。

运行新 benchmark 之前，还要审计评价器本身：正确参考程序应通过，破坏关键单位／对照／身份的程序应失败，等价正确实现不应被误拒。该检查用于验证测量工具，不作为 FarField 的科学成绩。纯自然语言解释暂时没有通用可靠的确定性裁判；需要独立领域审核的部分必须明确列出，不能用多模型一致冒充真值。
